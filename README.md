**既存Worker `rakuten-auto-affiliate` と既存D1をそのまま使用します。新規D1を作成しないでください。**

## デプロイ・稼働開始

1. 既存のGitHubリポジトリへ、このZIPをディレクトリ構造ごと上書きして、既存Cloudflare Workerにデプロイ。
2. Cloudflareの **Worker → 設定 → 変数とシークレット** で変数 `AUTO_PUBLIC_ORIGIN` に **実際の公開サイトのHTTPS URL** を設定（例はダミー。URLを推測して設定しないこと）。
3. 既存のSecret `RAKUTEN_APP_ID`, `RAKUTEN_ACCESS_KEY`, `RAKUTEN_AFFILIATE_ID`, `AI_ADMIN_TOKEN`, `THREADS_ACCESS_TOKEN`, `ADMIN_PANEL_PASSWORD` をそのまま維持する。**値をコードやGitHubに書かないこと。**
4. `wrangler.jsonc` の Cron Trigger がデプロイされたことを確認。管理者画面の「自動投稿」で初期状態が「停止」「20件」であることを確認。
5. テスト前に楽天・Threads APIの接続、AIの利用可能枠と掲載内容の確認、広告表記とアフィリエイト規約を確認する。
6. 管理者画面でONに切り替えて保存。公開投稿を試す場合だけ「今すぐ1件テスト投稿」を使う。**これは本番の公開投稿になる。**

## 必ず確認する制約

- **本番投稿未検証。** Cloudflare上の実API接続と課金・制限の検証が必要です。Cron Triggerの発火時間には実行遅延があり得ます。
- **自動画像添付は無効。** 楽天のAPI画像をSNSへ転載できる権利の確認が商品ごとにできるまで無条件転載しないためです。既存の手動画像添付（個別の許諾確認）は維持。
- **話題性そのものの外部トレンドデータは未連携。** 現段階の選定はランキング・価格・商品説明の情報量を使います。
- Threadsへの送信結果が不明な場合、重複事故を避けるため自動再送しません。失敗したジョブは履歴を見て管理者が確認してください。
- 一日の20件は達成保証ではなく目標上限です。失敗やAPI制限があれば投稿数は減ります。全投稿商品に記事生成するためWorkers AIの従量課金・制限にも注意。
- 旧D1テーブルを削除しません。新テーブルは初回の管理者アクセスまたはCronで自動作成。
